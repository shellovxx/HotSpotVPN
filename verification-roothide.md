# Проверка RootHide — 8 октября 2026

Устройство: iPhone 11 Pro Max / iOS 16.6.1 / Relaxin / RootHide; ElleKit 1.2 и CCSupport установлены. Проверка выполнена через SSH. Секреты, профиль VPN и сетевые захваты не включены в репозиторий.

| Проверка | Результат |
|---|---|
| Установка трёх `.deb` | `dpkg` подтверждает состояние `ii`, архитектура `iphoneos-arm64e` |
| Подпись и ABI | arm64 и arm64e PAC00; современная сборка clang 16 / ld64 951.9 |
| Logos | Пять исходных модулей, включая контроллер Настроек успешно обработаны и скомпилированы |
| Профиль Happ | Runtime-проба: includeAllNetworks=0, enforceRoutes=0, excludeAPNs=0, excludeLocalNetworks=1 |
| APNs | `HappAPNsScope` загружен в `apsd`; после перезапуска TCP 5223 ESTABLISHED с исходным адресом туннеля |
| Happ DNS | `HappAPNsDNS` загружен в работающий Tunnel.appex |
| Основной HotspotVPN | Библиотека загружена в `misd`, CC-модуль — в SpringBoard; пользователь подтвердил кнопку |
| DNS-дополнение | `HotspotVPNDNS` загружен в `bootpd`; 10 runtime-проверок sendto/sendmsg проходят для Cloudflare, Google, своего адреса, неверного адреса и выключенной подмены |
| Настройки | Пользователь подтвердил страницу; загрузчик проверен после исправления иконки: iconImage=yes, 29×29; ресурсы 29/58/87 px для 1×/2×/3×; пять specifiers и три значения настроек подтверждены |
| Реальная раздача Wi-Fi | Второй телефон получил DHCP-адрес; пользователь подтвердил работающий интернет |
| Интернет на iPhone | HTTPS example.com, github.com, cloudflare: HTTP 200 через системный API |
| APNs-фильтр | 17 случаев проходят |
| DHCP/DNS-парсер | 29 случаев проходят |
| Логи | У новых dylib отсутствуют импорты NSLog/syslog; в основном пакете удалены прямые вызовы NSLog, повторная подпись выполнена |

Основной HotspotVPN перенесён RootHide Converter из исходного бинарного пакета версии 1.0. Его исходников нет; Logos используется в Happ APNs Tweak и DNS-дополнении. Патч логов изменяет только инструкции прямого вызова NSLog (по одному вызову в каждой архитектуре твика и CC-модуля), а не глобальное поведение журналирования.

Известные границы проверки: специально вызванный APNs fallback 443, доставка конкретного уведомления и смена сети с блокировкой экрана не проверены. Данный перенос не добавляет kill switch; DNS-дополнение не запрещает клиентам DoH/DoT, IPv6 или свой DNS. DHCP option 6 проверен тестовыми OFFER через установленную библиотеку в отдельном процессе; значения сохранены вызовами установленного контроллера Настроек от пользователя mobile на устройстве с временным bridge101; исходные настройки восстановлены, временный интерфейс удалён. Захват ответа реальному Wi-Fi-клиенту не получен, поскольку раздача отключилась до захвата. Проверка UDP-хуков не заменяет такой захват и отдельно не покрывает BPF-путь системного bootpd.
