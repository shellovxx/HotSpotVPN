# HotspotVPN — настройка DNS

Тестовая сборка `0.1.0~rc1` для rootless iPhone 11 Pro Max / iOS 16.6.1, Dopamine и ElleKit. Установлена и проверена 6 октября 2026 года. Дополнение к оригинальному HotspotVPN 1.0; не заменяет его файлы.

## Настройки

Пункт **HotspotVPN** содержит переключатель, Cloudflare (`1.1.1.1`), Google (`8.8.8.8`) и свой IPv4. Используется оригинальная иконка CC-модуля `Icon.png` / `@2x` / `@3x`, размер **29 pt**, вместо большого варианта `SettingsIcon.png` размером 60 pt. Иконка берётся из установленного оригинального пакета.

Пресет по умолчанию — Cloudflare. Переключатель в RC выключен: получение ответов через VPN ещё не прошло проверку. Обновление пакета сохраняет настройки. Клиентам нужно переподключиться или обновить DHCP-аренду.

## Проверки на устройстве

Проверялись реальные пакеты USB-клиента:

| Режим | DHCP OFFER | DHCP ACK при выдаче аренды |
|---|---|---|
| Cloudflare | 1.1.1.1 | 1.1.1.1 |
| Google | 8.8.8.8 | 8.8.8.8 |
| Свой DNS | 9.9.9.9 | 9.9.9.9 |
| Выключено | Штатный DNS | Штатный DNS |

INFORM и неверный IPv4 также проверены. После установки RC повторные OFFER/ACK прошли; новых падений `bootpd` после исправлений нет. Пользователь подтвердил панель и её элементы управления. Окончательный размер иконки требует визуального подтверждения пользователем. Wi-Fi отдельно не проверялся.

Нативная сборка Procursus Clang 16 / ld64 951.9: `-O2 -DNDEBUG -Wall -Wextra -Werror`, подписанная dylib arm64e PAC00, subtype `0x80000002`. Сборка оптимизирована, но **не выпущена как production**. Переносимое ядро прошло 28 тестов, включая 20 000 случайных входов, усечения, overload, VLAN и checksums.

## Оставшийся сбой DNS

В связке **Happ 6.0.0 + HotspotVPN** UDP-запросы USB-клиента к Cloudflare и Google доходят с `bridge100` до VPN-интерфейса `utun7`, но ответов нет. Проверенные IP/UDP checksums корректны. Тестовые запросы Cloudflare не обнаружены на `pdp_ip0`; это наблюдение конкретных запросов, не доказательство отсутствия всех DNS leaks.

Штатный DNS точки доступа разрешил `example.com`, а `youtube.com` и `www.youtube.com` получили SERVFAIL. TCP-соединения, открытые SSH-сервером самого iPhone, успешно разрешили `youtube.com` и `example.com` через Cloudflare и Google. Это проверяет TCP-путь с телефона, не TCP-путь клиента. UDP с самого телефона и работа остальных UDP-приложений не установлены.

Предлагаемый фикс: локальный DNS-прокси принимает UDP-запросы клиентов, обращается к выбранному серверу через TCP с iPhone и возвращает ответы. Нужно проверить перенаправление, возврат ответов и отключение VPN. Прокси в пакет не включён. В таком прокси не должно быть автоматического отката к DNS оператора.

## Реализация

Hook загружается только в `bootpd`. Меняет существующую option 6 в OFFER/ACK, сохраняя размер пакета; пересчитывает ненулевой UDP checksum для Ethernet. Все слоты DNS заменяются выбранным адресом. Отсутствующая option 6 не добавляется.

Перехватываются `sendto`, `sendmsg`, `write`, `writev`, `ioctl`. Sandbox телефона запрещает BPF `BIOCGETIF`, поэтому успешный `BIOCSETIF` отслеживается с проверкой интерфейса `bridge…` и идентичности символьного устройства через `fstat`. Повторное связывание с другим интерфейсом сбрасывает запись. Для UDP проверяются порты 67/68 и server identifier интерфейса точки доступа.

Это выбор DHCP DNS. Собственные DNS клиента, DoH/DoT, IPv6 RDNSS/DHCPv6 и старые аренды не контролируются. Неверный IPv4 оставляет штатный ответ без изменений.

## Сборка и удаление

Theos, совместимый Apple clang и SDK iOS 16.5:

```sh
make clean package FINALPACKAGE=1 DEBUG=0
```

Для готовой dylib без dpkg-deb на хосте:

```sh
python3 scripts/package.py --binary /path/HotspotVPNDNS.dylib --output /path/HotspotVPN-DNS.deb
```

Проверка архитектуры запрещает упаковку без подписанной arm64e PAC00 slice. Результаты устройства и SHA256 — в `validation.json`. Пароли, конфигурации VPN, crash logs и pcap в архив не включены.

Удаление дополнения: `dpkg -r local.hotspotvpndns`. `postrm` перезапускает `bootpd`, выгружая hook; оригинальный HotspotVPN и пользовательские настройки сохраняются.

Источники: [RFC 2132, option 6](https://www.rfc-editor.org/rfc/rfc2132#section-3.8), [Apple udpv4_transmit](https://github.com/apple-oss-distributions/bootp/blob/main/bootplib/udp_transmit.c), [Apple BPF transport](https://github.com/apple-oss-distributions/bootp/blob/main/bootplib/bpflib.c).
