# Проверка HotspotVPN DNS 1.0.0

Дата: 6 октября 2026 года. Устройство: iPhone 11 Pro Max, iOS 16.6.1, rootless Dopamine, ElleKit; оригинальный HotspotVPN 1.0 и Happ 6.0.0. Проверенный клиент — Windows по USB. Трафик проходил через `bridge100` → `utun7`.

## UDP после установки production

Npcap отправлял Ethernet/IPv4/UDP запросы прямо в адаптер iPhone, чтобы отдельный VPN Windows не подменял путь. Ответы сопоставлялись по IP, портам и случайным transaction ID DNS/STUN либо originate timestamp NTP. Все ответы имеют корректный UDP checksum. Повторы предусмотрены на 0, 1 и 3 секунде; общий предел — 10 секунд.

| Протокол | Сервер | Проверка | Результат | От начала |
|---|---|---|---|---|
| DNS UDP 53 | 1.1.1.1 | youtube.com | NOERROR, 4 ответа | 1363 мс |
| DNS UDP 53 | 8.8.8.8 | youtube.com | NOERROR, 4 ответа | 1492 мс |
| DNS UDP 53 | 1.1.1.1 | example.com | NOERROR, 2 ответа | 1481 мс |
| STUN UDP 19302 | 74.125.250.129 | Binding request | Binding success | 1417 мс |
| STUN UDP 3478 | 162.159.207.0 | Binding request | Binding success | 1384 мс |
| STUN UDP 53 | 162.159.207.0 | Не-DNS payload на порту 53 | Binding success | 1406 мс |
| NTP UDP 123 | 162.159.200.123 | Time request | Ответ, stratum 3 | 1362 мс |
| NTP UDP 123 | 162.159.200.1 | Time request | Ответ, stratum 3 | 1481 мс |

Во всех восьми случаях к моменту ответа было отправлено два одинаковых запроса. Захваты не устанавливают, какой слой задерживает или теряет первый запрос и к какой отправке относится ответ. Полная матрица перед установкой production тоже прошла с повторами. Дополнение не меняет маршрутизацию UDP, настройки Happ или оригинальный HotspotVPN. Предыдущие одиночные пробы с таймаутами не подтверждают блокировку всего UDP.

Прямой контроль через основной Ethernet ПК: `youtube.com` получил NXDOMAIN от указанных публичных DNS, `example.com` разрешился, Cloudflare STUN/NTP получили ответы; Google STUN в контроле не ответил. Поэтому наличие ответа по пути USB → iPhone → VPN проверялось отдельно.

DNS в production получил нетранкированные ответы по UDP, TCP-fallback не потребовался. Автоматический переход при таймауте зависит от резолвера. Переход после ответа с флагом TC описан в [RFC 7766](https://www.rfc-editor.org/rfc/rfc7766).

Определения служб: [Google STUN](https://webrtc.org/getting-started/peer-connections), [Cloudflare STUN, порты 3478 и 53](https://developers.cloudflare.com/realtime/turn/), [Cloudflare NTP](https://developers.cloudflare.com/time-services/ntp/).

## Проверка сотового интерфейса

Сравнены точные UDP payload восьми тестовых запросов со случайными идентификаторами. На `bridge100` и `utun7` захвачено по 16 отправок; на `pdp_ip0` — **0 совпадений**. На сотовом интерфейсе также захвачены восемь фоновых UDP DNS-пакетов самого телефона, относящихся к Apple Push, а не к запросам теста.

Это проверка конкретных IPv4-запросов, не полное доказательство отсутствия DNS leaks. Трафик самого iPhone, самостоятельный DNS клиента, DoH/DoT и IPv6 дополнением не контролируются. Raw pcap и фоновые домены в релиз не включены.

## DHCP и установка

В исходной проверке OFFER/ACK подтверждены для Cloudflare, Google, своего DNS 9.9.9.9 и выключенного режима; проверены INFORM и неверный IPv4. После установки 1.0.0 повторены:

- OFFER/ACK с Cloudflare: option 6 содержит 1.1.1.1.
- Установка без существующих настроек: создан включённый Cloudflare; OFFER/ACK содержат 1.1.1.1.
- Обновление со своим DNS: сохранён 9.9.9.9; OFFER/ACK содержат 9.9.9.9.
- В конце восстановлен включённый Cloudflare.

Пользователь подтвердил наличие панели и элементов управления. Для иконки использован стандартный asset 29 pt; окончательный вид после изменения размера отдельно пользователем не подтверждён. Новых падений `bootpd` после исправлений прототипа не обнаружено.

Оптимизированная dylib: Procursus Clang 16 / ld64 951.9, arm64e PAC00 `0x80000002`, `-O2 -DNDEBUG -Wall -Wextra -Werror`, подпись ldid. SHA256 установленной dylib совпадает с упакованной. Пакет `local.hotspotvpndns` версии 1.0.0 установлен; оригинальный пакет остался версии 1.0.

Переносимый C-парсер прошёл 28 тестов, включая 20 000 случайных входов. Проверены содержимое пакета, подпись и отказ упаковщика от неподходящей архитектуры.

## Границы результата

DNS, STUN и NTP по UDP работают в проверенной связке. Выбор DNS через DHCP готов к выпуску для проверенного устройства. Измеренная задержка первого ответа остаётся наблюдением, а не исправленным сетевым дефектом. Wi-Fi, другие VPN, другие модели iPhone, произвольные UDP-приложения и поведение при отключении VPN отдельно не проверялись. Дополнение не обеспечивает принудительный перехват DNS или kill switch.
